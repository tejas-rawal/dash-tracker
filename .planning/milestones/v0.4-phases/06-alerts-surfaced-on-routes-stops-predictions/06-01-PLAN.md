<objective>
Embed currently-active service alerts, trimmed to a public response summary, onto `GET /api/v1/routes/all` and `GET /api/v1/routes/:shortName` (ALRT-05, ALRT-06). This is the phase's tracer: it builds the `ServiceAlertSummary` response-shape type, the `mapToServiceAlertSummary(ies)` mapping function, and `ServiceAlertRepository.getActiveAlertsForRoute()` — the shared building blocks Plan 06-02 reuses to expand alert embedding to stop responses (ALRT-07/08).

Purpose: Prove the full model -> repository -> service -> DI-wiring path for alert embedding end-to-end on one side (routes) before expanding to the other (stops), per D-01 through D-04 in `06-CONTEXT.md`.
Output: `RouteWithAlerts`-shaped route objects returned by `BusRouteService.getAgencyRoutes()`/`getAgencyRoute()`, wired through `busRoutes.ts` into the two live route endpoints.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Public HTTP client -> route endpoints | Unauthenticated internet clients call `GET /api/v1/routes/all` / `GET /api/v1/routes/:shortName`; the server now returns embedded alert content it previously kept internal (Phase 5 ingested it but never surfaced it). |
| DASH/Swiftly upstream -> ServiceAlertRepository | The server trusts upstream-sourced alert text/IDs (ingestion itself is unchanged, owned by Phase 5). |
| Route/alert ID matching (D-03) | `ServiceAlert.informedRouteIds` (upstream-sourced) is matched against internal `BusRoute.id` (DASH `/info` API-sourced) inside `ServiceAlertRepository.getActiveAlertsForRoute`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Tampering | `ServiceAlertRepository.getActiveAlertsForRoute` (ID matching) | low | accept | `informedRouteIds` and `BusRoute.id` both originate from the same trusted DASH/Swiftly system; no user-controlled input reaches the match; worst case is a display-only alert omitted or mismatched, no auth/integrity impact. |
| T-06-02 | Information Disclosure | `GET /api/v1/routes/all`, `GET /api/v1/routes/:shortName` (alert embedding) | low | accept | Alert content (`headerText`/`descriptionText`/`cause`/`effect`) is public transit-service information intended for riders; D-01 already excludes `url`/`informedRouteIds`/`informedStopIds` from the response, limiting exposure to only what riders need. |
| T-06-03 | Denial of Service | `BusRouteService.getAgencyRoutes` (O(routes x active-alerts) recompute per request) | medium | mitigate | Bounded by Phase 5's 5-minute-poll-refreshed in-memory alert set (no per-request upstream call, no unbounded growth); embedding stays a single in-memory `.filter()`/`.includes()` pass, consistent with the existing per-request recompute pattern already used for predictions. |
