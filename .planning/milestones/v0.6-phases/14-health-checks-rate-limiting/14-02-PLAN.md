<objective>
Stop any single client IP from exhausting the live DASH upstream. The four endpoints that call DASH on every request share one per-IP limit of 60 requests per minute. The 61st request in a window gets 429 with `Retry-After`, in the API's usual `{ error, details }` shape. One warn line is logged per offending IP per window, and that line never carries rider coordinates.

Purpose:
- RATE-01: live-upstream endpoints are limited per client IP and answer 429 with `Retry-After`.
- ROADMAP SC3 (first half): the 429 itself, the window reset, and per-IP keying at the limiter level.
- Plan 14-03 finishes SC3 through the real app's trust-proxy setting, and SC4 / RATE-02 across every unlimited endpoint.

Output:
- `express-rate-limit@8.7.0`, pinned exactly and installed only after a blocking-human legitimacy checkpoint.
- `src/server/api/middleware/upstreamRateLimit.ts`: the factory plus the one shared instance.
- The limiter attached to the four D-11 handlers.
- A real-app E2E (`rateLimit.test.ts`) and a minimal-app behavior suite (`upstreamRateLimit.test.ts`).

Decisions honored:
- D-09: the established library with its in-memory store. Version 8.7.0 was checked against Express 4.21 / Node 20, and its types were read: `RateLimitInfo.used`, `AugmentedRequest`, `Options.logger`, `RateLimitRequestHandler.resetKey`.
- D-10: one shared instance.
- D-11: four routes; each SSE connect counts once.
- D-12: 60 requests per 60_000 ms, as named constants.
- D-13: the `{ error: "Too Many Requests", details }` body.
- D-14: draft-8 `RateLimit` / `RateLimit-Policy` headers, legacy headers off.
- D-15: one warn per IP per window, with no query string.
- D-16: the limiter is attached per handler, never router-wide or app-wide.

Claude's-discretion choices (CONTEXT):
- The module is `src/server/api/middleware/upstreamRateLimit.ts`, exporting `createUpstreamRateLimiter()` and the shared `upstreamRateLimiter`.
- The first rejection in a window is detected with `(req as AugmentedRequest).rateLimit.used === UPSTREAM_RATE_LIMIT + 1`. The CONTEXT example's counter field is untyped in v8 (RESEARCH Pitfall 2), so `used` replaces it.
- Header flavor is draft-8 (RESEARCH alternatives table).
- Library validation messages are routed through a message-only Winston adapter (Phase 12 D-12 logging rule).

Ordering note:
- The blocking-human legitimacy checkpoint (Task 1) comes before the tracer, because the tracer installs the package.
- The checkpoint is a gate, not work. It costs almost no context, and the continuation agent starts the tracer fresh.

Spec-less probe fallback (no SPEC.md):
- Edges: all four RATE-01 edge items (boundary, precision, idempotency, concurrency) are resolved explicitly as truths. One extra backstop truth covers open SSE streams.
- Prohibitions:
  - Recall surfaced these candidates: logging rider coordinates; cutting off open rider streams; throttling riders behind a shared NAT; the limit being dodged with spoofed headers; logging every 429; double-counting a request; leaking library error objects.
  - Kept: a privacy prohibition (no coordinates or query string in logs) and a values prohibition (never end an open rider stream).
  - Dropped: shared-NAT throttling is the locked D-12 value (RESEARCH A1 records the risk). Log flooding, double counting and error-object leakage are routine engineering, pinned as truths.
  - Canon: header spoofing is canon security, covered by plan 14-03's threat model and /gsd-secure-phase, so it is not minted here.

Runtime facts (dist/index.cjs):
- When hits exceed the limit and standardHeaders or legacyHeaders is on, the library sets Retry-After = max(0, ceil((resetTime - Date.now()) / 1000)) BEFORE calling handler. With both off there is no Retry-After (RESEARCH Pitfall 3).
- MemoryStore.increment mutates the hit count synchronously, so concurrent requests count exactly. A window resets when resetTime <= Date.now(), so faking only Date moves windows (RESEARCH Pitfall 7).
- The default keyGenerator is ipKeyGenerator(req.ip, 56): it maps IPv4-mapped ::ffff:127.0.0.1 to 127.0.0.1 and groups IPv6 by /56.
- Validations run once per limiter instance and report through logger.error(ValidationError) (ChangeWarning goes to logger.warn). The message ends with "See https://express-rate-limit.github.io/<CODE>/ for more information.".
  - ERR_ERL_UNEXPECTED_X_FORWARDED_FOR fires when an X-Forwarded-For header arrives and app.get("trust proxy") === false (the Express default).
  - ERR_ERL_DOUBLE_COUNT fires if one request is counted twice by the same store.
  - ERR_ERL_CREATED_IN_REQUEST_HANDLER flags instances created inside a handler.
