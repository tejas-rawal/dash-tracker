<objective>
Add a Server-Sent Events endpoint that lets a client subscribe to live-updating arrival predictions for a stop, backed by one shared 30-second upstream poll loop per subscribed stop (starting on first subscriber, stopping when idle, resuming on the next subscriber), while the existing REST predictions endpoint keeps working unchanged as an independent fallback/initial-load path. Both REST and SSE responses report a `generatedAt` freshness timestamp.

Purpose: Gives the future Expo/React Native client a live-updating predictions feed without hammering the upstream DASH API, per the v0.2 milestone goal and locked decisions D-00a/D-00b (SSE over WebSocket, one shared poll loop per stop).
Output: New `PredictionStreamService` + `PredictionStreamController`, a new `GET /api/v1/predictions/stream` route, and a `generatedAt` field threaded through both the REST and SSE response shapes.
</objective>

Implement `async function poll(stopId: string): Promise<void>`: look up `loops.get(stopId)`; if the entry no longer exists (loop was torn down), return immediately. Otherwise `try` calling `predictionService.getPredictionsForStop(stopId)`; on success, set `entry.lastData` to the result and invoke every callback in `entry.subscribers` with it (fan-out — this is the mechanism that guarantees exactly one upstream call serves every subscriber for that stop, LIVE-02). On failure (`catch`), do NOT re-throw, do NOT clear the interval, and do NOT touch `entry.lastData` — per D-04, subscribers keep the stale-but-last-good payload. Implement `async function subscribe(stopId, onUpdate)`: if `loops.get(stopId)` is undefined, `await predictionService.getPredictionsForStop(stopId)` — let any rejection (NotFoundError/UpstreamApiError) propagate uncaught so the caller sees it and no loop entry is ever created for a stop whose first fetch failed. On success, build the `StreamLoop` entry with `subscribers: new Set([onUpdate])`, `lastData` set to the fetch result, and `timer: setInterval(() => { void poll(stopId); }, POLL_INTERVAL_MS)`; store it via `loops.set(stopId, entry)`; return `{ initialPayload: <the fetch result>, unsubscribe: () => unsubscribeFrom(stopId, onUpdate) }`.
