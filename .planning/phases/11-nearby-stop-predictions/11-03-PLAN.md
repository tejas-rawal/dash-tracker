<objective>
Close the two Phase 11 verification gaps. Both come from one root cause, review CR-01: `isValidNearbyEntry` checks that each `destination.predictions` is an array but never checks its elements, and the shared `mapToDestinations` dereferences every element unguarded.

1. SC5 / NEAR-09. A `[null]` element throws a TypeError. The request returns 500, the raw TypeError text reaches the client, and every valid stop is lost. After this plan the malformed entry is dropped with one `logger.warn` and the valid stops return 200.
2. Prohibition "MUST NOT fabricate or default arrival data". A `["x"]` or `[{}]` element passes the guard and is served as an empty prediction in a 200 response, with no warn. After this plan it is dropped and logged the same way.

The fix follows the verifier's prescription. Every prediction element must be a non-null object with finite-number `min`/`sec`/`time` and string `tripId`/`vehicleId`, which are the five fields the mapper copies. Otherwise the whole entry is dropped with one warn. The change is confined to `NearbyPredictionService.ts`. The shared mapping, `/predictions`, `/stops/nearby`, the controller and every existing test assertion stay unchanged. Existing test files only gain rows and tests.

Purpose: one bad element in one route's upstream entry no longer takes down "what's arriving around me" for every nearby stop, and a rider is never shown an arrival with no time, trip or vehicle.
Output: the per-element guard in `NearbyPredictionService.ts`, ten new malformed-element rows plus one no-fabrication test in `NearbyPredictionService.test.ts`, and one two-row route E2E case in `predictionRoutes.test.ts`.
</objective>

1. It does not close either gap. Once the guard stops the TypeError, the malformed-element path can no longer reach the 500 branch, and Task 1's E2E asserts that no internal error text reaches the client on that path.
2. 3. Scoping it to NearbyPredictionController alone would make that controller diverge from PredictionController and VehicleController, which echo error.message the same way (review IN-04). The lasting fix is one shared controller error-response helper that returns a generic 500 body and logs server-side, adopted by all three controllers together. That touches `/predictions` and `/vehicles`, which are out of this gap's scope.

Recommended follow-up: one `/gsd-quick` task that extracts that helper for PredictionController, VehicleController and NearbyPredictionController, covering WR-02 and IN-04 together.
