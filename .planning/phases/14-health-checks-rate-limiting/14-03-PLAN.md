<objective>
Finish the client-identity half of rate limiting, and prove that only the live routes are limited.
- The limiter keys on the real client IP. That is the socket address by default (spoof-proof), or the address that a configured number of trusted reverse proxies saw.
- Every in-memory endpoint stays unlimited, including the new health probes, even for an IP that is currently limited.

Purpose:
- RATE-01 / ROADMAP SC3, second half: a different IP is unaffected and the limited IP is served again after the window. This is proven through the real app's trust-proxy configuration, not only on a minimal app.
- RATE-02 / ROADMAP SC4: routes, stops, favorites/recents and health never answer 429.
- D-17: the validated, documented `TRUST_PROXY_HOPS` env var.
- A real-process smoke covers app.ts, which has no unit test and is excluded from coverage, together with the probes and the limiter.

Output:
- `TRUST_PROXY_HOPS` in the Zod env schema, plus `app.set("trust proxy", ...)` in both app.ts and the test app.
- `trustProxy.test.ts` (TRUST_PROXY_HOPS=1 E2E).
- The env validation matrix.
- `.env.example`, `.claude/CLAUDE.md` and `AGENTS.md` docs.
- The RATE-02 never-limited rows and the default-0 spoof test in `rateLimit.test.ts`.
- The phase-level coverage and lint gates.

Decisions honored:
- D-16: unlimited endpoints are proven unlimited.
- D-17: a non-negative integer, default 0, applied with `app.set`; an invalid value fails startup; documented with the other env vars.
- D-18: deployment-agnostic. A plain hop count works behind any LB or PaaS, with no platform-specific config.

RESEARCH Pattern 5 is followed. The strict digits-only schema is used because `z.coerce.number()` would turn an empty value into 0 instead of failing startup.

Depends on 14-01 (the health routes appear in the RATE-02 rows) and 14-02 (the limiter and rateLimit.test.ts).

Spec-less probe fallback (no SPEC.md):
- Edges: all three RATE-02 edge items (boundary, precision, concurrency) are resolved explicitly as truths.
- Prohibitions:
  - Recall surfaced these candidates: spoofed X-Forwarded-For evading the limit; trusting every proxy hop; a rider's in-memory lookups throttled because the same IP is limited on live routes; probes rate-limited so an LB marks a healthy instance down; misconfiguration failing silently.
  - None was minted as a bespoke prohibition. Header spoofing and permissive trust are canon security (OWASP), covered by this plan's threat model (T-14-12, T-14-13) and /gsd-secure-phase. Throttled lookups and limited probes are the RATE-02 truths themselves. Silent misconfiguration is the D-17 validation truth.
</objective>

| public client → in-memory endpoints and probes | Must stay reachable regardless of the live-route limit (RATE-02) |
