Planning-time facts (verified 2026-11-10 against this checkout; do not re-derive):
- `src/test/setup.ts` pins `CORS_ALLOWED_ORIGINS=http://localhost:8081` (plan 18-04), so `src/test/app.ts` (`createApp()`) allows exactly that origin in every test file.
- Behavior without CORS, measured on the current app: `OPTIONS /api/v1/predictions?stop=stop-1` → 200, body `GET,HEAD`, `Allow: GET,HEAD`, no `RateLimit` header (the limiter never runs). `OPTIONS /api/v1/favorites` without `X-Device-Id` → 400 `{"error":"Bad Request","details":"X-Device-Id header is required"}`. `GET /api/v1/no-such` → Express 404 with `content-security-policy` and `x-content-type-options` headers.
- With plan 18-04's origin callback, cors 2.8.6 leaves requests from a disallowed origin or with no Origin untouched. For the allowed origin it sets `Access-Control-Allow-Origin` (exact) and `Vary: Origin`, plus `Access-Control-Expose-Headers: Retry-After,RateLimit,RateLimit-Policy` on non-OPTIONS responses. It answers OPTIONS itself with 204, `Access-Control-Allow-Methods: GET,HEAD,PUT,PATCH,POST,DELETE`, `Access-Control-Allow-Headers` echoing the request's `Access-Control-Request-Headers`, and `Vary: Origin, Access-Control-Request-Headers`.
- `rateLimit.test.ts` holds the patterns to reuse: a single `app.listen(0)` server per file, `upstreamRateLimiter.resetKey("127.0.0.1")` in `beforeEach` (supertest connects from ::ffff:127.0.0.1), `remainingOf(response)` parsing `r=` from the `RateLimit` header, a 60-request loop then the 61st, and logger spies muted. Before any load, `/api/v1/predictions?stop=stop-1` answers 503 (repository guard) and still spends the bucket. `/api/v1/routes/all` answers 503 with `Retry-After: 5`.
- `streamCap.test.ts` holds the patterns for streams: `vi.mock("../services/PredictionService", ...)` so streams open without DASH or data, `mockService.getPredictionsForStop.mockResolvedValue(...)`, `trackOpenResponses(server)`, and in `afterEach` destroying every stream and waiting until `openResponses()` is 0. The cap is 5 open streams per client IP and answers 429 with `Retry-After: 5` and `{ error: "Too Many Requests", details: "Too many open prediction streams from this client; close one before opening another" }`.
- `src/test/streamClient.ts` `connectStream({ port, path, clientIp? })` sets only `X-Forwarded-For`. It swallows pre-response socket errors; that is the deferred Phase 17 hang. Leave that behavior alone and add only the origin option.
- Biome counts `useNamingConvention` warnings on object-literal keys like `Origin:`. Set headers with supertest's `.set("Origin", ...)` and use the lowercase key `origin` inside the stream client, so the warning count stays at 36.
